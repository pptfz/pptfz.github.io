# 字段选择算符

**字段选择算符（Field selectors）** 允许你根据一个或多个资源**字段**的值筛选 Kubernetes 对象。下面是一些字段选择算符查询的例子：

- `metadata.name=my-service`
- `metadata.namespace!=default`
- `status.phase=Pending`

下面这条 `kubectl` 命令会选择所有 `status.phase` 字段值为 `Running` 的 Pod：

```bash
kubectl get pods --field-selector status.phase=Running
```

:::caution 字段选择算符本质是"资源过滤器"
默认情况下不应用任何选择算符/过滤器，意味着选定指定类型的全部资源。因此 `kubectl get pods` 与 `kubectl get pods --field-selector ""` 是等价的。
:::

## 支持的字段

字段选择算符的支持情况因 Kubernetes 资源类型而异。**所有资源类型都支持 `metadata.name` 和 `metadata.namespace` 字段**。使用不支持的字段选择算符会产生错误，例如：

```bash
kubectl get ingress --field-selector foo.bar=baz
```

```none
Error from server (BadRequest): Unable to find "ingresses" that match label selector "", field selector "foo.bar=baz": "foo.bar" is not a known field selector: only "metadata.name", "metadata.namespace"
```

### 支持字段的完整列表

| 资源类型 | 支持的字段 |
| -------- | ---------- |
| Pod | `spec.nodeName`、`spec.restartPolicy`、`spec.schedulerName`、`spec.serviceAccountName`、`spec.hostNetwork`、`status.phase`、`status.podIP`、`status.podIPs`、`status.nominatedNodeName` |
| Event | `involvedObject.kind`、`involvedObject.namespace`、`involvedObject.name`、`involvedObject.uid`、`involvedObject.apiVersion`、`involvedObject.resourceVersion`、`involvedObject.fieldPath`、`reason`、`reportingComponent`、`source`、`type` |
| Secret | `type` |
| Service | `spec.clusterIP`、`spec.type` |
| Namespace | `status.phase` |
| ReplicaSet | `status.replicas` |
| ReplicationController | `status.replicas` |
| Job | `status.successful` |
| Node | `spec.unschedulable` |
| CertificateSigningRequest | `spec.signerName` |

### 自定义资源字段

所有自定义资源类型都支持 `metadata.name` 和 `metadata.namespace` 字段。

此外，CustomResourceDefinition（CRD）的 `spec.versions[*].selectableFields` 字段声明了自定义资源中哪些其他字段可用于字段选择算符。详细信息参见 CRD 文档中"自定义资源的可选字段"（selectable fields）一节。

## 支持的运算符

字段选择算符可以使用 `=`、`==` 和 `!=` 运算符（`=` 与 `==` 含义相同）。例如，下面这条 `kubectl` 命令选择不在 `default` 命名空间中的所有 Kubernetes Service：

```bash
kubectl get services --all-namespaces --field-selector metadata.namespace!=default
```

:::caution 不支持基于集合的运算符
字段选择算符**不支持**集合类运算符（`in`、`notin`、`exists`）——这是它与标签选择算符的重要区别。需要集合语义时只能借助标签选择算符或客户端侧过滤。
:::

## 链式选择算符

与标签选择算符等类似，字段选择算符可以用逗号分隔的列表链接在一起。下面这条 `kubectl` 命令选择所有 `status.phase` 不等于 `Running` 且 `spec.restartPolicy` 等于 `Always` 的 Pod：

```bash
kubectl get pods --field-selector=status.phase!=Running,spec.restartPolicy=Always
```

## 多种资源类型

你可以跨多种资源类型使用字段选择算符。下面这条 `kubectl` 命令选择不在 `default` 命名空间中的所有 StatefulSet 和 Service：

```bash
kubectl get statefulsets,services --all-namespaces --field-selector metadata.namespace!=default
```

:::tip 与标签选择算符的配合
`--field-selector` 和 `-l`（标签选择）可以在同一条 kubectl 命令中同时使用，实现"字段 + 标签"的双重过滤，例如按 `status.phase` 字段过滤再按应用标签收窄结果。
:::

## 我的总结与避坑清单

1. 字段选择算符筛的是**对象自身字段**（如 `status.phase`、`metadata.namespace`），不是 metadata.labels——按自定义标签过滤请用 `-l`，两者别混用。
2. 所有资源都支持 `metadata.name` 和 `metadata.namespace`，但其余字段"按类型开关"：用错字段会直接报 `BadRequest` 错误，报错信息里通常会列出该类型允许的字段。
3. 只支持 `=`、`==`、`!=` 三种运算符，没有 `in`/`notin`/`exists`，也没有正则；模糊或集合过滤要靠 `grep`/`jq` 或标签选择算符。
4. 逗号连接多个条件是"与"关系，如 `status.phase!=Running,spec.restartPolicy=Always`。
5. Event 是字段选择算符的高频场景，例如 `kubectl get events --field-selector involvedObject.kind=Pod,involvedObject.name=my-pod` 快速定位某个 Pod 的事件。
6. 排查调度问题时常用 `kubectl get pods --field-selector spec.nodeName=<node>` 列出某节点上的 Pod；Pod 的 `status.phase` 只有 Pending/Running/Succeeded/Failed/Unknown 等有限取值，拼写错误只会得到空结果而不是报错。
7. CRD 默认只支持按 name/namespace 过滤；要让自定义资源的某个 spec 字段可被字段选择，需要在 CRD 的 `selectableFields` 中显式声明。
8. 大规模集群中字段选择算符通常比全量拉取后本地过滤更高效（过滤在 API 侧完成），但个别字段索引情况随版本变化，超慢查询时可改用按 namespace 收窄 + 客户端过滤的方式。
9. `--field-selector` 可与多种资源类型并列使用（如 `statefulsets,services`），但要注意各类型必须都支持所用字段，`metadata.namespace` 这类通用字段最安全。
