Rocky 10 已移除 ntpdate，用 chrony 替代：常驻的 `chronyd` 负责自动同步，无需 cron 定时任务（原来的 `chronyc -a makestep` 定时任务在现代 chrony 上需要认证，实际执行不了，已删除）。时间校准分两层：`makestep 1.0 -1` 让偏差超 1 秒时由 chronyd 自动跳变（含挂起恢复场景）；真发现大偏差时用上面的 `ntpdate` 命令（内部执行 `chronyd -q`）手动强制跳变一次即可。

:::info 22.04 / 24.04 / 26.04 最小化安装的差异与结论
**需要做的**（脚本已全部幂等处理，三个版本通用）：换 apt 阿里源、关 swap（Server 最小化安装默认有 `/swap.img`）、关 ufw、装 chrony 配国内 NTP + `makestep 1.0 -1`、装 net-tools（最小化安装不带 netstat）、ulimits、pip 源。

**不需要做的**（与 Rocky 的关键差异）：
- 无 epel：Ubuntu 没有 EPEL 概念，常用工具都在官方源里
- 无 SELinux：Ubuntu 用 AppArmor，默认策略不影响运维操作，**不建议关闭**
- 不动 NetworkManager：Server 版网络栈是 netplan + systemd-networkd，禁用 NM 反而可能断网

**三版本差异点**：22.04 用传统单行格式 `/etc/apt/sources.list`，24.04/26.04 改为 deb822 格式的 `/etc/apt/sources.list.d/ubuntu.sources`（脚本两个文件都处理）；24.04/26.04 启用 PEP668 管控系统级 pip 装包（脚本自动加 `--break-system-packages`）；默认 swap 大小不同但处理方式相同。
:::

```shell
#!/usr/bin/env bash
#
# Ubuntu 22.04 / 24.04 / 26.04 最小化安装（Server）优化脚本
# 幂等设计：重复执行安全；版本差异自动适配（见各段注释）
# 双模式设计：
#   root（或 sudo）执行 → 系统级优化 + 用户级配置写给登录用户（SUDO_USER）
#   普通用户直接执行   → 只做用户级优化（自己的 bashrc/pip 源/别名），系统级部分跳过

set -e

# ===== 兼容守卫：用 sh 执行时自动切换到 bash =====
# Ubuntu 的 sh 是 dash（无 source、不支持 bash 特性），sh yh.sh 会忽略 shebang 强制用 dash。
# 这段让 dash 启动后立即 exec 到 bash 重新运行，sh/bash 执行效果完全一致
if [ -z "${BASH_VERSION:-}" ]; then
  exec bash "$0" "$@"
fi

# ===== 0. 版本检测（22.04 / 24.04 / 26.04）=====
. /etc/os-release
UBU_VER="${VERSION_ID}"
echo "当前 Ubuntu 版本: ${UBU_VER} (${VERSION_CODENAME:-})"

# ===== 用户级配置的目标用户 =====
# 原则：系统级操作（apt/swap/systemctl）需要 root，但用户级配置（bashrc/pip 源/别名）
# 应写给"真正登录的用户"而非 root——sudo 执行时 $HOME 指向 /root，$SUDO_USER 才是登录用户
# 例：pptfz 登录后执行 sudo sh yh.sh → 配置写入 /home/pptfz；root 直接执行 → 写入 /root
TARGET_USER="${SUDO_USER:-$USER}"
TARGET_HOME="$(getent passwd "$TARGET_USER" | cut -d: -f6)"
echo "用户级配置目标: ${TARGET_USER} (${TARGET_HOME})"

# ===== root 判定：系统级操作仅 root 可做 =====
if [ "$(id -u)" -eq 0 ]; then
  IS_ROOT=1
  echo "运行模式: root —— 系统级 + 用户级 全部执行"
else
  IS_ROOT=0
  echo "运行模式: 普通用户 —— 仅执行用户级配置，系统级部分跳过（补全请用 sudo 执行）"
fi

if [ "$IS_ROOT" -eq 1 ]; then
# ============================================================
# 第一部分：系统级优化（需要 root）
# ============================================================

# ===== 1. 换 apt 源为阿里云 =====
# 版本差异：22.04 用传统单行格式 /etc/apt/sources.list；
#          24.04/26.04 用 deb822 格式 /etc/apt/sources.list.d/ubuntu.sources
# 两个文件都做替换，存在哪个换哪个
# 注意匹配模式必须带 /ubuntu 路径：只替换主机名的话，原路径里的 /ubuntu 会被保留，
# 拼出 mirrors.aliyun.com/ubuntu/ubuntu 双层路径导致 404
# 幂等：备份只在第一次做（.bak 不存在才 cp），且已配置过阿里源则整体跳过
if [ -f /etc/apt/sources.list ] && ! grep -q 'mirrors.aliyun.com' /etc/apt/sources.list; then
  [ -f /etc/apt/sources.list.bak ] || cp /etc/apt/sources.list{,.bak}
  sed -i 's|http://cn.archive.ubuntu.com/ubuntu|https://mirrors.aliyun.com/ubuntu|g;
          s|http://archive.ubuntu.com/ubuntu|https://mirrors.aliyun.com/ubuntu|g;
          s|http://security.ubuntu.com/ubuntu|https://mirrors.aliyun.com/ubuntu|g' /etc/apt/sources.list
fi
if [ -f /etc/apt/sources.list.d/ubuntu.sources ] && ! grep -q 'mirrors.aliyun.com' /etc/apt/sources.list.d/ubuntu.sources; then
  [ -f /etc/apt/sources.list.d/ubuntu.sources.bak ] || cp /etc/apt/sources.list.d/ubuntu.sources{,.bak}
  sed -i 's|http://cn.archive.ubuntu.com/ubuntu|https://mirrors.aliyun.com/ubuntu|g;
          s|http://archive.ubuntu.com/ubuntu|https://mirrors.aliyun.com/ubuntu|g;
          s|http://security.ubuntu.com/ubuntu|https://mirrors.aliyun.com/ubuntu|g' /etc/apt/sources.list.d/ubuntu.sources
fi
apt-get update

# ===== 2. 安装常用工具与 chrony =====
# net-tools 最小化安装不自带（netstat 命令依赖它）；
# 安装 chrony 时会自动停用 systemd-timesyncd（Ubuntu 默认用它同步时间），二者不共存
apt-get install -y net-tools curl wget vim lsof bash-completion chrony git

# ===== 3. 时区与时间同步（chrony，与 Rocky 部分同一套逻辑）=====
timedatectl set-timezone Asia/Shanghai
CONF=/etc/chrony/chrony.conf    # 注意：Ubuntu 的 chrony 配置路径与 Rocky 不同
# 幂等：先删掉默认 pool 和之前追加过的 server 行，再追加，避免重复堆叠
sed -i '/^pool /d; /^server ntp.aliyun.com/d; /^server ntp.tencent.com/d' ${CONF}
cat >> ${CONF} << 'EOF'
server ntp.aliyun.com iburst
server ntp.tencent.com iburst
EOF
# 与 Rocky 部分相同：偏差超 1 秒随时跳变（默认 makestep 1 3 只管启动后前 3 次）
sed -i 's/^makestep .*/makestep 1.0 -1/' ${CONF}
grep -q '^makestep' ${CONF} || echo 'makestep 1.0 -1' >> ${CONF}
grep -n '^makestep' ${CONF}
systemctl enable --now chrony
systemctl restart chrony
timedatectl | grep -E 'Time zone|synchronized'

# ===== 4. 关闭 ufw 防火墙（三个版本默认均未启用，幂等）=====
if command -v ufw >/dev/null 2>&1 && ufw status 2>/dev/null | grep -q 'Status: active'; then
  ufw disable
fi
# AppArmor 保留不关：Ubuntu 用 AppArmor 而非 SELinux，默认策略不影响运维操作

# ===== 5. 关闭 swap =====
# 三个版本 Server 最小化安装默认都有 /swap.img（大小不一），处理方式与 Rocky 相同
# 幂等：跳过已注释的行，避免重复执行时加多层 #
swapoff -a
sed -i '/^\s*#/!{ /\sswap\s/s/^/#/ }' /etc/fstab
# 若存在 zram 设备（个别镜像带），一并卸载

# ===== 10. 安装并配置 grc（源码安装 + 命令输出着色，按目标用户登录 shell 写不同配置）=====
# 安装：clone 官方仓库 + 官方 install.sh（仅 root 可做；普通用户模式下 grc 已由 root 装好则直接配置）
#       安装路径：bin→/usr/bin、conf→/usr/share/grc、grc.conf→/etc、grc.sh→/etc/profile.d/、grc.zsh→/etc
# 配置：依据官方 README/源码，bash 的 grc.sh 必须先设 GRC_ALIASES=true 才会创建别名（grc.zsh 无此要求）；
#       bash 启用文件 /etc/profile.d/grc.sh（源码与 Debian 包默认位置），zsh 为 /etc/grc.zsh
# 幂等：已安装/已配置则跳过；候选路径逐个探测，兼容源码安装（/usr/local）与发行版包的路径差异
if ! command -v grc >/dev/null 2>&1; then
  if [ "$IS_ROOT" -eq 1 ]; then
    rm -rf /tmp/grc-src
    # clone 和安装一条链：任一步失败都走 else 分支提示跳过，不会中断脚本
    if git clone --depth 1 https://github.com/garabik/grc.git /tmp/grc-src \
       && (cd /tmp/grc-src && ./install.sh /usr ""); then
      echo "grc: 源码安装完成"
    else
      echo "grc: git clone 或 install.sh 失败（网络原因？），跳过安装"
    fi
  else
    echo "grc: 未安装且当前为普通用户，跳过安装（请用 sudo 执行本脚本安装）"
  fi

GRC_CFG=""
RCFILE="${TARGET_HOME}/.bashrc"
case "$USER_SHELL" in
  */zsh)
    RCFILE="${TARGET_HOME}/.zshrc"
    for f in /etc/grc.zsh /usr/local/etc/grc.zsh /usr/share/grc/grc.zsh; do
      if [ -f "$f" ]; then GRC_CFG="$f"; break; fi
    done
    ;;
  *)
    for f in /etc/profile.d/grc.sh /etc/grc.sh /usr/local/etc/profile.d/grc.sh; do
      if [ -f "$f" ]; then GRC_CFG="$f"; break; fi
    done
    ;;
esac
if [ -n "$GRC_CFG" ] && ! grep -q 'grc' "$RCFILE" 2>/dev/null; then

    echo 'GRC_ALIASES=true' >> "$RCFILE"
  fi
  echo "[ -s $GRC_CFG ] && . $GRC_CFG" >> "$RCFILE"
  # 新建的 rc 文件属主会变成 root，改回目标用户
  if [ "$IS_ROOT" -eq 1 ] && [ "$TARGET_USER" != "root" ]; then
    chown "${TARGET_USER}:${TARGET_USER}" "$RCFILE"
  fi
fi
```
